# 06 · 联机与位面连接

> 文档状态：世界观与兼容原则已确定，网络方案和数据权限待技术验证
> 依赖：[世界观与叙事规则](02-世界观与叙事规则.md)、[核心循环与搜打撤规则](03-核心循环与搜打撤规则.md)

## 1. 联机目标

联机不是独立于主循环之外的模式，而是空间锚点系统的自然扩展：

- 每名玩家拥有自己的炉界残片；
- 玩家通过炉火锚点连接另一块残片；
- 玩家可以访问他人家园，或以同一个位面锚点共同进入关卡；
- 长期服务器可以持有一块持续发展的共享炉界；
- 单人游戏即使永远不联机，也能完整游玩。

核心体验类似《我的世界》的“玩家世界可以被访问”，同时保留搜打撤单局实例。

## 2. 多玩家世界观

炉界在灾难中分裂为许多相互隔离的残片。每块残片都有自己的：

- 炉火；
- 稳定土地；
- 规则书；
- 传送装置；
- 独立存档和发展状态；
- 求援信号。

每一名玩家都是某块残片中醒来的 **守火者**。因此多人同时存在不会与“唯一主角”冲突。

首次发现其他玩家时，规则书可以显示：

> 检测到另一处稳定炉火。
> 检测到未登记守火者。
> 对方锚点正在请求连接。

轻量 Meta 提示可写为：

> 当前观察源：2。
> 空间稳定程度：正常。

此类内容只偶尔出现，不应妨碍联机操作信息。

## 3. 三种联机形态

### 3.1 访问其他玩家的炉界

玩家通过邀请、好友信息或服务器入口获得一枚炉火坐标，并在传送设施中建立临时或保存连接。

访问者可以在房主授权下：

- 参观家园；
- 使用工作台、商店和传送设施；
- 交换物品；
- 帮助建造与整理；
- 共同抵御黑暗入侵；
- 组成队伍进入关卡。

#### 权限层级建议

| 权限 | 可执行操作 |
|---|---|
| 参观 | 移动、查看展示、使用指定公共设施 |
| 访客 | 使用公共容器和交易，不能修改建筑 |
| 建造者 | 放置和调整授权区域建筑 |
| 管理者 | 管理共享仓库、锚点和防御设施 |
| 房主 | 世界设置、成员权限和关键设施控制 |

拆除、删除、移动核心设施等高影响操作必须由明确权限控制。

### 3.2 共同进入搜撤关卡

玩家先在一座炉界中组队，由队伍选择位面锚点并建立同一次连接。

关卡共享：

- 地图实例；
- 怪物与环境状态；
- 危险阶段；
- 规则事件；
- 撤离装置状态。

玩家分别拥有：

- 角色状态；
- 背包和手持物；
- 装备和消耗品；
- 倒地与撤离结果。

默认规则：

- 玩家可以分别撤离；
- 已撤离玩家不能重新进入本局；
- 队友可救援倒地玩家；
- 失联玩家的物品留在关卡内；
- 队友可以把其战利品带出；
- 某些特殊撤离点可要求多人同步。

### 3.3 长期共享炉界

一名玩家、主机或独立服务器持有炉界存档，多名玩家长期共同建设。

适合：

- 好友生存档；
- 长期公共服务器；
- 共同家园建设；
- 持续世界时间与入侵；
- 多人仓储和分工。

第一位建立该世界的玩家可拥有最高权限，但世界观上所有加入者都是守火者，不强调唯一主角。

## 4. 锚点与网络对象的对应

| 世界观对象 | 游戏/网络含义 |
|---|---|
| 炉界残片 | 一个家园世界存档或服务器世界 |
| 守火者 | 玩家角色与个人数据 |
| 炉火坐标 | 好友邀请、服务器地址或世界标识 |
| 炉火锚点 | 指向特定家园世界的连接记录 |
| 位面锚点 | 创建搜撤关卡实例的内容与随机种子入口 |
| 精确锚点 | 固定场景或特殊副本标识 |
| 返回信标 | 玩家在当前关卡中的归返/撤离关联 |
| 炉界静止 | 单人存档或主机世界关闭后的暂停状态 |

世界观术语用于表现，底层实现仍需使用明确稳定的世界 ID、玩家 ID、存档版本和会话 ID。

## 5. 数据边界

为了兼容不同联机方式，概念上分离两类数据。

### 5.1 守火者数据

倾向跟随角色：

- 外观；
- 装备与随身背包；
- 已学习配方；
- 图鉴和已发现规则；
- 个人成就；
- 部分锚点知识。

### 5.2 炉界数据

跟随世界存档：

- 建筑、地形和装饰；
- 炉火等级与能量；
- 领土范围；
- 世界仓库和容器；
- 功能 NPC；
- 已安装锚点；
- 入侵进度；
- 世界时间与权限列表。

### 5.3 尚未确定的携带模式

可以支持两种配置，但首版只需实现一种：

**自由携带模式**

- 玩家携带自己的角色、装备和物资进入；
- 撤离所得可带回个人炉界；
- 适合好友联机和轻松体验；
- 需要防止高等级物资直接破坏新世界进度。

**世界独立角色模式**

- 每个炉界为加入者建立独立角色；
- 外部物资不能带入；
- 适合长期公共服务器和公平开荒；
- 数据与角色管理成本更高。

当前建议：好友联机优先采用易理解的自由携带方向，但必须经过技术和经济验证后再定案。

## 6. 战利品归属

### 6.1 关卡中

物品以实体存在：谁持有，谁承担重量、风险和丢失可能。

### 6.2 撤离后

可提供世界设置：

- **个人所得**：玩家带出的物品进入自己的结算栏；
- **共享结算**：物品进入当前炉界的共同结算区；
- **手动分配**：由队伍在安全区自行交易。

好友快速组队默认建议采用个人所得，减少强制分配和纠纷。

### 6.3 家园容器

多人家园至少区分：

- 私人容器；
- 公共容器；
- 仅管理者可用容器；
- 炉火与恢复必需品的保护库存。

## 7. 多人难度

不要只按人数提高怪物生命值。优先改变：

- 进攻方向；
- 怪物数量和组合；
- 需要多人分工的机关；
- 同时发生的灯具或锚点故障；
- 搬运大型物品的机会；
- 队友辨认和不同步信息；
- 撤离信号数量异常。

关卡中的物资产出需要随人数调整，但不能简单按人数等比增长，否则多人会成为唯一最优选择。

## 8. 多人规则怪谈

多人异常应产生交流和判断，而不是依赖恶意整蛊。

示例：

- 系统显示的返回信号比队伍多一个；
- 某个怪物使用离队玩家的外观或名字；
- 不同玩家看到的门或道路状态不同；
- 只有部分成员看见规则书警告；
- 一名玩家听到错误撤离广播；
- 入侵时出现一个没有登记的守火者信号。

公平原则：

- 至少有一种办法辨认异常；
- 不复制或生成玩家真实语音；
- 不能让正常网络延迟看起来像不可区分的怪谈机制；
- 关键操作以服务器/房主权威结果为准；
- 怪谈 UI 与真实断线、错误提示应有最终可辨识方式。

## 9. 上线、掉线与离线解释

### 玩家加入

> 新的守火者已抵达。其来源仍未登记。

### 玩家掉线

> 一道观察已经中断。
> 炉火将暂时保存其位置。

技术上应明确处理：角色是否留在原地、进入保护状态、自动撤离或安全断开。该规则待确定，不能只靠世界观文案掩盖。

### 玩家重新连接

> 连接恢复。守火者继续活动。

### 世界关闭

单人或主机存档关闭时，炉界进入“静止状态”：

- 作物和生产暂停；
- 炉火不继续消耗；
- 入侵与灰雾停止推进；
- NPC 和地图状态被保存。

独立服务器可继续运行，因为服务器承担世界的持续状态。

## 10. 联机兼容的开发约束

即使首版先做单人，核心代码和数据也应避免以下假设：

- 不假设场景中永远只有一个玩家；
- 交互、伤害、拾取和容器操作要记录执行者；
- 关卡实例与玩家个人存档分开；
- 物品拥有稳定唯一标识，避免复制与丢失；
- 世界建筑操作必须可验证权限；
- 撤离状态按玩家记录，不只按整局记录；
- 随机地图应由可同步种子或权威端结果生成；
- 保存数据需要版本号和迁移策略；
- UI 文案中的“你”不要硬编码为唯一守火者。

这不代表首版就实现网络同步，而是避免底层模型只能支持单人。

## 11. 推荐迭代顺序

### 阶段 A：单人闭环

- 单人炉界；
- 单人位面实例；
- 搜索、背包、死亡、撤离和结算；
- 家园存档。

### 阶段 B：好友共同搜撤

- 房主创建会话；
- 玩家同步、怪物同步、拾取归属；
- 倒地救援；
- 分别撤离与结算；
- 断线重连基础处理。

### 阶段 C：访问玩家家园

- 炉火锚点邀请；
- 家园状态同步；
- 容器与建筑权限；
- 共同防守。

### 阶段 D：长期共享炉界

- 专用服务器或持久主机；
- 长期成员与权限；
- 世界持续运行；
- 存档迁移、防作弊和管理工具。

个人开发不应跳过前两个阶段直接建设大型公共服务器。

## 12. 已确定 / 待验证 / 暂不做

### 已确定

- 每名玩家拥有独立炉界残片的世界观；
- 可通过锚点访问其他家园或共同进入关卡；
- 单人体验完整；
- 默认合作而非 PvP；
- 多人允许独立撤离；
- 单人世界关闭后暂停，不施加离线惩罚。

### 待验证

- 首发是否含联机；
- 队伍人数上限；
- 自由携带或世界独立角色；
- 掉线时角色处理；
- 战利品默认归属；
- 房主制、P2P 或独立服务器技术路径；
- 跨炉界交易限制；
- 是否允许访客使用房主已解锁锚点。

### 暂不做

- 默认 PvP 与家园掠夺；
- 大型开放世界所有玩家共用一张地图；
- 首版公共服务器生态；
- 复杂公会、拍卖行和跨服市场；
- 利用玩家真实语音生成拟态内容。
