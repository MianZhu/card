# 07 · MVP 范围与开发顺序

> 文档状态：建议执行方案，具体技术排期需结合现有工程评估
> 依赖：[产品定位与设计支柱](01-产品定位与设计支柱.md)、[核心循环与搜打撤规则](03-核心循环与搜打撤规则.md)

## 1. MVP 的唯一目标

MVP 不负责证明所有系统都能实现，只验证最关键的问题：

> **玩家找到一件很值钱的东西后，是否会因为舍不得放弃它而经历一段有趣的逃亡；成功撤离后，是否愿意用所得改善家园并立刻再去一次。**

若这个循环不好玩，增加位面数量、剧情、联机、自动生成和大量数值都无法解决根本问题。

## 2. 最短可玩闭环

```text
炉界准备
  ↓
选择唯一锚点
  ↓
进入一张小型关卡
  ↓
搜索普通物和一件高价值物
  ↓
遇见怪物并作出打、躲、丢弃或绕路决策
  ↓
成功撤离或死亡
  ↓
出售 / 投炉 / 留作升级
  ↓
获得一次可感知成长
  ↓
再次出发
```

## 3. MVP 必须包含

### 3.1 炉界

- 一小块固定家园地图；
- 一座可补充能量的炉火；
- 一个仓库或安全库存；
- 一个出售/处理战利品的设施；
- 一个基础工作台或升级入口；
- 一座传送门；
- 保存与加载。

### 3.2 玩家

- 移动；
- 基础交互；
- 一种攻击或击退方式；
- 生命/受击或等价失败状态；
- 背包；
- 手持大型物品；
- 死亡与返回炉界。

### 3.3 单张关卡

- 一张手工制作的小型地图；
- 进入点；
- 普通撤离点；
- 普通搜索房间；
- 一个高价值区域；
- 门、容器和可打碎物；
- 一种清晰的危险升级方式；
- 至少一条直接影响玩法的规则。

建议使用 [灰雾废镇](05-位面关卡与规则怪谈.md#8-首张完整关卡候选灰雾废镇)，但不是不可修改的硬性要求。

### 3.4 物品

建议最低内容量：

- 约 10 种普通回收物；
- 约 3 种特殊或危险回收物；
- 至少 1 件必须手持的大型高价值物；
- 1—2 种消耗品；
- 1 种炉火燃料；
- 1 个能带来永久成长的材料或部件。

数量是开发建议，不是最终数值。

### 3.5 怪物

建议最低内容量：

- 1—2 种可击退普通怪；
- 1 种不能靠正常攻击解决的大型威胁；
- 如开发量允许，再加入 1 种规则型怪物。

每种怪物必须有不同应对方式，不能只换模型和属性。

### 3.6 结算与成长

- 撤离成功后保存战利品；
- 死亡后丢失本局所得；
- 战利品至少可出售和投炉；
- 一部分材料可升级仓库、背包、工具或炉火中的一个；
- 玩家在数局内看到明确变化。

## 4. MVP 暂不包含

- 完整联机；
- 访问其他玩家家园；
- 长期共享服务器；
- 多个位面主题；
- 完整程序化地图生成；
- 大量 NPC 和剧情任务；
- 角色好感；
- 多种职业或复杂技能树；
- 完整换装系统；
- 大规模家园自动生产；
- 复杂黑暗入侵；
- 多结局或最终 Boss；
- 公会、拍卖行、赛季和商业化系统；
- 完整 Meta 叙事演出。

这些功能可以保留接口或数据概念，但不进入首个可玩版本。

## 5. 开发阶段

### 阶段 0：纸面冻结

先确定最少参数：

- 目标平台和输入；
- 摄像机与移动；
- 基础攻击方式；
- 背包最简模型；
- 单局目标时长范围；
- 死亡损失；
- 唯一地图主题；
- 唯一成长项。

输出：一页冻结表，不继续扩写大系统。

### 阶段 1：无美术灰盒搜撤

实现：

- 移动、碰撞、交互；
- 门和容器；
- 背包与拾取；
- 怪物追逐；
- 进入与撤离；
- 死亡和战利品清除。

验收：连续试玩中，玩家知道自己为何继续搜、为何撤、为何失败。

### 阶段 2：战利品与家园闭环

实现：

- 回收物价值；
- 大型物搬运；
- 结算；
- 仓库；
- 出售与炉火；
- 一项永久升级。

验收：成功撤离能改变下一局准备，玩家愿意重复游玩。

### 阶段 3：规则与氛围

实现：

- 一条环境规则；
- 一种规则型或不可对抗怪物；
- 灰雾、灯光、声音提示；
- 少量物品描述和场景痕迹；
- 开场与规则书基础页。

验收：玩家无需长文本就能感到世界异常，并能逐渐学会规则。

### 阶段 4：家园与入侵原型

实现：

- 一个可建造或可修复区域；
- 一种防御设施；
- 一次简化灰雾入侵；
- 防守失败后的可恢复后果。

验收：外出所得确实影响家园安全，家园不会变成纯菜单。

### 阶段 5：联机技术样机

仅在单人闭环稳定后进行：

- 两名玩家加入同一会话；
- 同步移动、门、容器和怪物；
- 同一物品不能被重复拾取；
- 倒地救援；
- 分别撤离；
- 结算无复制或丢失。

先验证好友共同搜撤，再考虑家园互访。

### 阶段 6：内容扩展

- 房间组件与地图变体；
- 更多回收物；
- 更多怪物；
- 第二位面；
- 家园装饰；
- 商人和研究；
- 完整黑暗入侵；
- 玩家家园连接。

## 6. 功能优先级

### P0：没有就不能验证核心

- 进入关卡；
- 搜索与拾取；
- 背包取舍；
- 怪物威胁；
- 撤离；
- 死亡损失；
- 战利品结算；
- 一项家园成长。

### P1：强化差异化

- 大型手持宝物；
- 灯光与灰雾；
- 规则型怪物；
- 回收物多用途；
- 简易家园建设；
- 黑暗入侵原型；
- 碎片叙事。

### P2：扩大留存与内容

- 多位面；
- 地图随机化；
- 商人和收藏；
- 装备流派；
- 更多家园设施；
- 好友共同搜撤。

### P3：长期平台化

- 家园互访；
- 共享炉界；
- 独立服务器；
- 大量装饰与换装；
- 长期内容更新框架。

## 7. 原型数据建议

仅作为起始测试，不视为正式定案：

| 项目 | 起始建议 |
|---|---|
| 地图 | 1 张手工地图 |
| 普通回收物 | 约 10 种 |
| 特殊回收物 | 约 3 种 |
| 怪物 | 2—3 种 |
| 环境规则 | 1 条 |
| 撤离方式 | 1 个普通撤离点 |
| 永久升级 | 1 项 |
| 家园设施 | 4—6 个必要交互点 |
| 叙事文本 | 开场、规则书基础页、少量物品说明 |

实际数量服从“完整闭环优先”，内容不足可以补，系统做散很难回收。

## 8. 验收清单

### 核心体验

- [ ] 玩家理解带回战利品才算获得；
- [ ] 玩家会因价值、体积或风险放弃某件物品；
- [ ] 至少一种怪物让玩家选择逃跑而非清怪；
- [ ] 危险升级有明显提示；
- [ ] 撤离过程存在紧张感；
- [ ] 死亡损失明确且可接受；
- [ ] 成功撤离能带来下一局可感知收益。

### 家园闭环

- [ ] 回收物能进入安全仓库；
- [ ] 至少有出售和投炉两种处理方式；
- [ ] 炉火状态可被玩家理解；
- [ ] 至少一个家园对象能永久改善；
- [ ] 退出和加载不会丢失关键状态。

### 叙事与氛围

- [ ] 开场不超过必要长度；
- [ ] 规则通过玩法体现，不只是一段文字；
- [ ] 美术可以是童话风，但世界不依赖童话故事解释；
- [ ] 玩家忽略背景文本也能正常完成一局。

### 联机兼容

即使尚未联机，也应确认：

- [ ] 交互可记录操作者；
- [ ] 撤离状态按玩家建模；
- [ ] 物品实例拥有唯一标识；
- [ ] 家园存档与角色数据可概念分离；
- [ ] 随机内容可由种子或权威结果复现。

## 9. 关键测试问题

每轮试玩重点记录：

1. 玩家第几分钟开始感觉背包取舍？
2. 玩家何时第一次主动决定撤离？
3. 玩家死亡是因为误判、操作失误，还是缺乏信息？
4. 哪类物品最容易让玩家产生“必须带回去”的欲望？
5. 怪物是在创造路线决策，还是仅仅拖延时间？
6. 玩家回家后最想做的是卖、升级、收藏还是马上再出发？
7. 玩家第二局的准备是否因第一局所得发生变化？
8. 连续五局后，重复感主要来自地图、物品还是怪物？

## 10. 文档与数据产出建议

进入开发前，后续应另建结构化资料，而不是继续扩写本篇：

- MVP 冻结表；
- 回收物正式数据表；
- 怪物行为表；
- 房间与生成点表；
- 装备/背包规则表；
- 单局经济模拟表；
- 测试记录与版本变更表。

旧 Excel 可作为素材来源，但不能直接视为新方案的最终数值。
