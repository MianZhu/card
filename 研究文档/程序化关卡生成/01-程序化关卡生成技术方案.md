# 程序化关卡生成技术方案

> 状态：基础规则已确定，布局算法尚未实现
> 更新日期：2026-09-01
> 适用范围：Godot 4.7 斜视角房间式搜撤关卡

## 1. 目标

关卡由策划手工制作的房间模板组成。程序根据关卡种子选择房间、匹配接口、计算坐标、避免重叠，并保证出生房、资源房和撤离房连通。

房间内部的地形、建筑、装饰和候选生成点均由策划手工设计。生成器不自动设计房间内部布局。

首版重点验证：

- 多大格房间能否稳定拼接；
- 斜视角 TileMap 是否能严格对齐；
- 同一种子能否复现相同布局；
- 玩家和怪物是否能实际通过房间接口；
- 宝箱、散落物和怪物能否按全局预算生成。

## 2. 已确定规则

1. 项目使用 Godot 4.7、2D 斜视角菱形 TileMap。
2. 生成算法只使用 TileMap 逻辑直角坐标，不使用屏幕像素坐标判断房间位置。
3. 一个关卡大格由 `16×16` 个 TileMap 小格组成。
4. 一个房间可以占用一个或多个大格，例如 T 形房间可占四个大格。
5. 每个房间选择一个实际占用的大格作为锚定大格，其局部大格坐标固定为 `(0,0)`。
6. 房间内部地形、建筑、宝箱点、散落物点、怪物点、出生点、撤离点和巡逻点由策划手工制作。
7. 房间接口只能位于房间占用形状的外轮廓。
8. 首版不在运行时旋转房间；不同朝向使用独立模板。
9. 所有正式房间都必须能从出生房到达。
10. 房间连接图连通与实际地形、碰撞、导航连通分别验证。
11. 种子是关卡生成的第一项输入。同一种子、生成版本、关卡配置和模板库产生相同结果。
12. 怪物可以原地徘徊、房间内巡逻或跨房间巡逻；跨房路线由关卡生成后建立的巡逻网络决定。

## 3. 术语

| 术语 | 英文/代码概念 | 含义 |
|---|---|---|
| 小格 | Tile Cell | TileMap 中一个小菱形格 |
| 大格 | Level Block | `16×16` 个小格组成的逻辑关卡单位 |
| 房间 | Room | 占用一个或多个大格的完整预制场景 |
| 锚定大格 | Anchor Block | 房间局部大格坐标 `(0,0)`，用于放置整个房间 |
| 占用形状 | Occupied Blocks | 房间占用的大格坐标集合 |
| 接口 | Room Port | 房间外轮廓上允许连接其他房间的开口 |
| 连接 | Connection | 两个兼容接口形成的逻辑关系 |
| 候选生成点 | Spawn Point | 策划手工放置、运行时可能被启用的位置 |
| 巡逻网关 | Patrol Gateway | 怪物穿过已连接房间接口时使用的路径节点 |
| 房间深度 | Room Depth | 从出生房沿连接图到该房间的最少连接数 |

## 4. 三层坐标体系

### 4.1 小格坐标

小格使用 `Vector2i` 表示，是 TileMap 的原生逻辑坐标。房间内部地形和生成点均最终对应小格坐标。

### 4.2 大格坐标

一个大格固定包含 `16×16` 个小格：

```gdscript
const TILES_PER_BLOCK := 16

func block_to_tile(block: Vector2i) -> Vector2i:
	return block * TILES_PER_BLOCK
```

示例：

```text
大格 (0,0) -> 小格起点 (0,0)
大格 (1,0) -> 小格起点 (16,0)
大格 (0,1) -> 小格起点 (0,16)
大格 (2,3) -> 小格起点 (32,48)
```

大格构成逻辑直角坐标系。屏幕上显示为菱形只是 TileMap 投影结果，不改变生成算法。

### 4.3 世界坐标

世界坐标只负责 Godot 中的显示、碰撞和角色移动。大格或小格转换为世界位置时统一使用 `TileMapLayer.map_to_local()`，不手写菱形投影公式。

```gdscript
func tile_offset(tile_map: TileMapLayer, cell: Vector2i) -> Vector2:
	return (
		tile_map.map_to_local(cell)
		- tile_map.map_to_local(Vector2i.ZERO)
	)
```

### 4.4 锚定大格

TileMap 没有“整张地图中心”概念。锚定大格是项目人为定义的房间放置基准。

每个房间必须选一个实际占用的大格作为 `(0,0)`。例如 T 形房间可定义为：

```text
(-1,0)  (0,0)  (1,0)
          (0,1)
```

```gdscript
occupied_blocks = [
	Vector2i(-1, 0),
	Vector2i(0, 0),
	Vector2i(1, 0),
	Vector2i(0, 1),
]
```

锚定大格不是房间的视觉中心，也不是菱形顶点。它只是房间局部大格坐标的零点。

## 5. 房间模板协议

每个标准房间至少包含以下元数据：

| 字段 | 类型 | 用途 |
|---|---|---|
| `room_id` | `StringName` | 模板稳定标识 |
| `category` | 枚举 | 出生、普通、红房、通道、分叉、死路、撤离等 |
| `occupied_blocks` | `Array[Vector2i]` | 房间占用的大格集合 |
| `weight` | `float` | 同类模板抽取权重 |
| `min_depth` | `int` | 最小房间深度 |
| `max_depth` | `int` | 最大房间深度，`-1` 表示不限 |
| `max_instances` | `int` | 单局最大实例数，`-1` 表示不限 |
| `estimated_traversal_time` | `float` | 仅通过房间的预计秒数 |
| `estimated_search_time` | `float` | 搜索房间的预计额外秒数 |

房间节点结构见《房间模板制作规范》。模板中不得包含玩家、HUD、相机或完整关卡管理逻辑。

## 6. 房间接口协议

### 6.1 接口职责

接口描述两个房间可以在哪里连接。接口不等于门：

- 接口负责拓扑、对齐、通行权限和连接规格；
- 门负责美术、开关、碰撞、动画和音效；
- 已连接接口可以是开放通道，也可以生成门；
- 两个房间连接时只生成一扇门。

### 6.2 接口字段

| 字段 | 含义 |
|---|---|
| `block` | 接口所在的房间局部大格 |
| `direction` | `NORTH/EAST/SOUTH/WEST` 逻辑方向 |
| `profile` | 接口规格，如 `normal`、`wide` |
| `edge_start` | 沿 16 小格边界的起始格，范围 `0..15` |
| `edge_length` | 开口占用的小格数量 |
| `allow_door` | 是否允许在连接处生成门 |
| `player_allowed` | 玩家是否可通过 |
| `enemy_size_limit` | 可通过的最大怪物体型等级 |

逻辑方向固定为：

```text
NORTH = ( 0,-1)
EAST  = ( 1, 0)
SOUTH = ( 0, 1)
WEST  = (-1, 0)
```

不要使用屏幕中的左上、右上、左下、右下命名接口。

### 6.3 接口匹配

两个接口至少满足以下条件才能连接：

1. 方向相反；
2. `profile` 相同；
3. `edge_start` 相同；
4. `edge_length` 相同；
5. 两个接口都位于各自房间占用形状的外轮廓；
6. 候选房间放置后不与已有房间重叠且不越界。

普通接口的最终开口宽度尚未确定，必须通过玩家、普通怪物、最大怪物和多人错身灰盒测试决定。生成算法只依赖配置，不写死门宽。

### 6.4 房间放置公式

房间 A 已放置，A 接口与候选房间 B 接口匹配时：

```gdscript
var b_origin := (
	a_origin
	+ a_port.block
	+ a_port.direction_vector()
	- b_port.block
)
```

随后将 B 的每个局部占用格转换为全局大格进行重叠和越界检查。

## 7. 确定性种子规则

参考《我的世界》的对外规则：玩家只输入或看到一个关卡种子。

```text
相同种子
+ 相同 generation_version
+ 相同关卡配置
+ 相同模板库及稳定顺序
= 相同生成结果
```

种子决定：

- 房间模板选择；
- 房间拓扑、坐标和接口连接；
- 出生房、红房和撤离房；
- 启用的宝箱与散落物候选点；
- 初始怪物生成点、怪物种类和巡逻策略。

实现必须遵守：

- 使用受控的 `RandomNumberGenerator`；
- 不使用系统时间参与已开始的生成；
- 不混用全局 `randi()`、`randf()`；
- 模板列表和候选列表先稳定排序再随机选择；
- 不依赖 `Dictionary` 或文件系统的不稳定遍历顺序；
- 回溯和重试同样由该种子确定，不临时换种子。

正式存档应记录 `seed`、`generation_version` 和最终布局。游戏升级后，同一种子允许像《我的世界》不同版本一样产生不同结果，但旧存档仍应按已保存布局恢复。

## 8. 关卡配置与预算

不固定每种形状房间的数量。生成器读取关卡配置和难度预算：

- 目标探索时间；
- 地图大格边界；
- 主路线最小/最大图距离；
- 红房数量或产出要求；
- 支路、死路和环路范围；
- 宝箱数量与总价值预算；
- 怪物威胁预算；
- 出生房与撤离房规则。

房间数量是满足时间、产出、路线和威胁目标的结果，不是首要目标。

## 9. 推荐生成流程

1. 接收玩家输入种子；未输入时由系统生成并保存。
2. 初始化确定性随机源并读取 `generation_version`。
3. 读取关卡难度、时间、产出和威胁配置。
4. 从稳定排序的模板库选择出生房、红房和撤离房。
5. 先生成抽象房间连接图，确定关键房间深度和主支路关系。
6. 从出生房开始，将连接图逐个嵌入大格坐标。
7. 匹配接口并通过公式计算候选房间锚定大格。
8. 使用 `occupied_blocks` 检查重叠和地图边界。
9. 失败时按确定顺序更换接口、模板或执行有限回溯。
10. 主结构完成后添加普通探索房、支路、死路和可选环路。
11. 对未使用接口执行封闭处理。
12. 验证房间连接图中所有正式房间可达。
13. 实例化房间场景并使用参考 TileMap 对齐世界位置。
14. 验证接口地面、碰撞、玩家通路和怪物导航。
15. 收集房间中手工放置的所有候选生成点。
16. 按产出预算启用宝箱和散落物点。
17. 按威胁预算启用怪物点并分配巡逻机制。
18. 连接已使用接口两侧的巡逻网关。
19. 输出种子、版本和生成报告。

## 10. 回溯与失败处理

多大格不规则房间可能因空间不足无法放置，因此禁止无限随机重试。

配置至少包含：

- 单个开放接口最大候选尝试次数；
- 单张地图最大回溯次数；
- 整图最大重建次数；
- 最大生成耗时或步骤数。

失败必须返回明确原因，例如：

- 没有兼容接口；
- 候选房间全部重叠；
- 房间超出地图边界；
- 红房无法满足最小深度；
- 撤离房没有合法位置；
- 最终图或实际导航不连通。

## 11. 未连接接口

接口最终状态包括：

| 状态 | 处理 |
|---|---|
| 已连接开放 | 移除封口，不生成门 |
| 已连接有门 | 移除封口，由关卡生成器生成一扇门 |
| 未连接 | 保留封口视觉和碰撞 |
| 特殊锁定 | 生成对应特殊门或永久封闭结构 |

房间模板需要提供封口和门锚点，但本阶段不实现门与封口运行时逻辑。

## 12. 四层验证

### 12.1 布局验证

- `occupied_blocks` 不重复；
- 锚定大格 `(0,0)` 被占用；
- 房间之间不重叠；
- 房间不超出配置边界；
- 接口位于占用形状外轮廓；
- 同一边上的接口范围不重叠。

### 12.2 拓扑验证

- 所有正式房间从出生房可达；
- 所有红房可达；
- 撤离房可达；
- 不存在孤立房间；
- 房间深度满足配置要求。

### 12.3 几何与玩家通路验证

- 匹配接口的门洞位置和宽度一致；
- 接口处存在连续地面；
- 已连接接口没有残留封口碰撞；
- 接口净空区域没有固定建筑；
- 玩家可以从房间内部测试点走到全部正式接口。

### 12.4 怪物导航验证

- 怪物导航区域在允许的接口处连通；
- 未连接或禁止怪物通过的接口不建立导航连接；
- 巡逻网关只连接本局实际使用的接口；
- 怪物体型与接口通行限制匹配。

## 13. 内容生成

房间内手工布置的是候选点，不代表每局全部启用。

关卡完成布局和连通验证后，统一收集：

- 宝箱候选点；
- 散落物候选点；
- 怪物候选点；
- 出生点；
- 撤离点；
- 巡逻点和巡逻网关。

生成器再按全局预算选择实际启用点，避免每个房间独立生成导致总产出和总威胁失控。

## 14. 怪物巡逻网络

巡逻分为三层：

1. 怪物机制决定巡逻模式；
2. 巡逻图决定宏观目标和房间关系；
3. `NavigationAgent2D` 决定如何绕过具体障碍。

房间内部由策划手工设置巡逻点和合法路线。允许跨房巡逻的接口提供巡逻网关。关卡生成完成后，只连接已使用接口两侧的网关。

首批模式：

- 原地徘徊；
- 房间内循环或往返；
- 相邻房间往返；
- 跨若干房间往返；
- 守卫宝箱或撤离点；
- 少量全图游荡怪物。

怪物实例应统一位于关卡运行时容器，不应成为出生房间的永久子节点。

## 15. 调试工具与报告

调试视图应显示：

- 种子和生成版本；
- 房间 ID、类别、锚定坐标和深度；
- `occupied_blocks`；
- 已连接与未连接接口；
- 出生到撤离路径；
- 红房位置；
- 怪物跨房巡逻连接；
- 重叠、越界或验证错误。

每次生成输出：

- 种子、版本、生成耗时和重试次数；
- 房间总数与分类统计；
- 主路线、支路、环路和死路数据；
- 红房深度；
- 宝箱候选数、实际数和价值预算；
- 怪物候选数、实际数和威胁预算；
- 巡逻路线与跨房连接数；
- 四层验证结果。

## 16. 首版范围

首个灰盒版本只要求：

- 一个出生房；
- 一个单格直通房；
- 一个多格 T 形房；
- 一个红房；
- 一个死路房；
- 一个撤离房；
- 不旋转；
- 树状连接图；
- 固定种子复现；
- 多格房间重叠检查；
- 接口匹配和未连接接口封闭；
- 玩家从出生房走到撤离房；
- 一只怪物能在两个已连接房间之间往返。

## 17. 暂不实现

- 完整建筑占格编辑器；
- 运行时房间旋转；
- 任意形状自动房间内部生成；
- 动态改变房间位置；
- 复杂多层地图；
- 全部现有房间一次性迁移；
- 正式经济平衡数值；
- 复杂特殊撤离与随机事件。

## 18. 待灰盒确认参数

- `normal` 接口的 `edge_start` 与 `edge_length`；
- 玩家、普通怪物和最大怪物所需净宽；
- 接口内侧净空深度；
- 首张地图边界与目标局长；
- 主路线和支路数量；
- 红房数量、深度与产出；
- 宝箱数量与总价值预算；
- 怪物威胁预算；
- 环路数量；
- 回溯和重建次数上限。
